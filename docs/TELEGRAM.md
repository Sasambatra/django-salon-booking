# Telegram-бот студии

**Русский** · [English](TELEGRAM.en.md)

Бот помогает владельцу следить за записями с сайта. Он показывает данные только
разрешённым Telegram-аккаунтам в личной переписке. Группы и каналы не поддерживаются.
В этой версии бот русскоязычный; язык сайта от него не зависит.

## Что уже реализовано

- Уведомления о временном резерве, успешной/неуспешной демо-оплате, отмене,
  полном демо-возврате и истечении резерва.
- Карточка с полным номером записи, услугой, мастером, клиентом, датой,
  московским временем, ценой и состоянием оплаты.
- Кнопки «Сегодня», «Завтра», «Ближайшие», «Сводка», «Помощь».
- Просмотр выбранной даты, поиск записи по полному номеру, страницы расписания.
- Сохранённая очередь, повторные попытки при временных сбоях и журнал доставки
  в защищённой админке сайта.

Бот получает сведения из той же PostgreSQL-базы, что и сайт. Он не подтверждает
платежи и не меняет записи по командам из Telegram. Оплата и возвраты остаются
демонстрационными. Финансовая сводка не означает реальных поступлений.

## 1. Создать бота

Откройте [официального BotFather](https://t.me/BotFather) в своём Telegram.
Отправьте `/newbot`: эта команда создаёт нового бота. Задайте отображаемое
название, например «Haircut Studio — записи», затем свободное имя пользователя,
которое заканчивается на `bot`.

BotFather выдаст **токен** — секретный ключ управления ботом. Не отправляйте его
в чат, не помещайте в скриншоты, команды терминала, README или Git.
В редакторе откройте приватный файл `.env` в корне проекта.
Впишите ключ после знака `=`:

```dotenv
TELEGRAM_ENABLED=false
TELEGRAM_BOT_TOKEN=
TELEGRAM_ADMIN_IDS=
```

`TELEGRAM_BOT_TOKEN` хранит ключ. Пока `TELEGRAM_ENABLED=false`, сайт не
создаёт уведомления. `.env` уже исключён из Git и должен иметь права `600`:
читать и изменять его может только владелец локального файла.
Пример `.env.example` должен оставаться без настоящих ключей.

## 2. Узнать свой Telegram ID

**Telegram ID** — постоянный числовой номер аккаунта, который используется
для проверки доступа. Имя вида `@username` для этого не подходит.

Рабочая папка терминала — корень вашего клона, где находится `manage.py`.
Команда ниже использует уже имеющиеся Bash, Python и библиотеки проекта:

- `bash` запускает командный файл;
- `scripts/run_telegram.sh` — путь к файлу, который читает приватный `.env`
  и запускает бота из существующей `.venv`;
- `--identify` включает режим определения номера: он сообщает отправителю
  только его собственный ID, без записей и уведомлений.

```bash
bash scripts/run_telegram.sh --identify
```

Ожидается `Telegram bot ready (identity only).`. Оставьте терминал открытым.
Откройте своего нового бота в Telegram, нажмите «Старт» или отправьте
`/whoami` — «кто я». Бот ответит вашим числовым ID. Никакого стороннего
бота для определения номера не требуется.

Скопируйте этот номер в `.env`:

```dotenv
TELEGRAM_ENABLED=true
TELEGRAM_ADMIN_IDS=ваш_числовой_ID
```

Здесь `ваш_числовой_ID` — пояснение, его нужно заменить цифрами без пробелов.
Несколько доверенных владельцев можно указать через запятую. Каждый получает
доступ ко всем записям студии и уведомлениям. Каждый должен сначала нажать
«Старт» в личном чате с ботом. Не добавляйте сюда аккаунты клиентов.

## 3. Запустить подключённого бота

Остановите режим определения номера сочетанием `Ctrl+C`.
В той же папке запустите тот же файл без дополнительного параметра:

```bash
bash scripts/run_telegram.sh
```

Ожидается `Telegram staff bot ready. Ctrl+C stops it.`. Скрипт перечитает `.env`.
Перезапустите и сайт, чтобы он тоже получил новые настройки из `.env`.
Запуск сайта описан в [README](../README.md#локальный-запуск).

Сайт и бот — два отдельных процесса: оставьте оба терминала открытыми.
Бот получает команды через исходящие HTTPS-запросы к Telegram, поэтому для
локальной работы публичный адрес сайта не нужен. Никакие библиотеки не
устанавливаются. Для круглосуточной работы впоследствии нужен постоянно
работающий сервер и настройка перезапуска/наблюдения за процессом.

## Команды и проверка

| Команда | Результат |
| --- | --- |
| `/start`, `/help` | Меню и справка |
| `/today` | Подтверждённые записи и действующие резервы на сегодня |
| `/tomorrow` | Такое же расписание на завтра |
| `/upcoming` | Предстоящие записи до конца седьмого дня, включая сегодня |
| `/date 2026-11-02` | Расписание выбранной даты, пример формата |
| `/today 2` | Вторая страница, по пять записей на странице |
| `/date 2026-11-02 2` | Вторая страница выбранной даты |
| `/booking UUID` | Полная карточка: замените UUID полным номером с сайта/уведомления |
| `/stats` | Число записей и сумма подтверждённых записей на сегодня, состояние очереди |
| `/whoami` | Собственный Telegram ID |

Создайте на сайте тестовую запись, выполните успешную демо-оплату, затем
отмените её не позднее чем за два часа до визита. В Telegram должны прийти
уведомления с соответствующими состояниями и полным демо-возвратом. Повтор
поддерживаемого запроса на сайте не создаёт новое уведомление того же события.
Время указано по Москве, деньги — в рублях. Имена и согласованная цена берутся
из сохранённой записи; изменение текущего каталога их не переписывает.
В расписании нет отменённых записей и просроченных резервов; карточка по полному
номеру позволяет посмотреть их историю состояний оплаты.

Если команда завершилась ошибкой, остановитесь и сохраните только её текст
без токена. Не вставляйте `.env` целиком в чат.

## Доставка и защита

Событие и запись уведомления сохраняются в одной операции базы: при откате
бронирования уведомление тоже исчезает. Сайт не ждёт ответа Telegram. Отдельный
бот отправляет сохранённый снимок события и записывает результат. Снимок резерва
может прийти уже после подтверждения при задержке доставки; заголовок события
описывает тот момент, а `/booking` показывает текущее состояние.

Для каждой пары «событие + запись + бот + получатель» существует одна строка
очереди. Успешные строки не отправляются повторно обычным проходом. Временные
сбои повторяются до пяти попыток с увеличением пауз; `retry_after` Telegram
приостанавливает доставку всему боту. Ошибки неверного запроса, токена или
блокировки переводят доставку в `Failed`. Тексты внешних ошибок не попадают
в журнал: сохраняются только безопасные описания/числовые коды.

При неоднозначном сетевом сбое или остановке между принятой Telegram отправкой
и записью результата возможен повтор сообщения. Bot API не предоставляет
ключа для устранения такого повтора `sendMessage`; абсолютная доставка
«ровно один раз» не заявляется. Бронирование от повтора сообщения не меняется.

В админке откройте **Telegram deliveries**. Виден текст, состояние, число
попыток и следующая попытка. После исправления причины выберите строки
`Failed` и действие **Retry failed Telegram deliveries**. Оно ставит их
обратно в очередь. Тексты содержат сведения о клиенте; защищайте доступ к базе,
резервным копиям и аккаунтам Telegram. Автоматическое удаление истории доставки
не настроено; для реальной эксплуатации нужно определить срок хранения.

Входящие команды обрабатываются только из личного чата, где отправитель
совпадает с номером чата. Проверяется числовой ID из `TELEGRAM_ADMIN_IDS`.
Измените список и перезапустите оба процесса, чтобы отозвать доступ:
неотправленные сообщения удалённому получателю получают `Revoked`.
Для команд действует ограничение 20 обращений в минуту на аккаунт. Текст
сообщений отправляется без HTML-разметки и без автоматического просмотра ссылок;
включена защита от обычного пересылания/сохранения в Telegram. Снимки экрана
и доступ к разблокированному телефону она не исключает.

Номер последней обработанной команды сохранён в базе отдельно для каждого бота.
После перезапуска обработанные команды пропускаются. При сбое после ответа,
но до сохранения номера, возможен повтор безопасного ответа с данными.
PostgreSQL-блокировка разрешает один процесс бота на базу.
Активный webhook — ранее настроенная пересылка Telegram на публичный адрес —
останавливает запуск; бот не удаляет чужую настройку автоматически.
Непрерывно работающий бот раз в минуту запускает общую проверку истёкших
резервов, чтобы их уведомления появлялись и без новых посетителей сайта.

Уведомления создаются только для новых событий после включения настройки.
Записи, существовавшие до подключения, доступны через команды просмотра.
При выключенном процессе очередь копится. При `TELEGRAM_ENABLED=false`
новые события в неё не добавляются. Смена токена того же бота сохраняет очередь;
совсем другой бот не отправляет старую очередь автоматически.

## Идеи следующих возможностей

1. **Напоминания клиентам** за сутки и за два часа: после безопасной привязки
   Telegram к аккаунту на сайте и явного включения уведомлений самим клиентом.
2. **Утреннее расписание владельцу** и отдельные представления для мастеров,
   где каждый видит только свои записи.
3. **Лист ожидания**: предложить освободившееся время заинтересованным клиентам
   без обещания брони до проверки доступности на сервере.
4. **Повторная запись**: кнопка перехода к выбору времени с прежним мастером.
5. **Перенос/отмена через бота**: после привязки аккаунта, проверки владельца
   записи и отдельного подтверждения, с теми же правилами и возвратами сайта.

Это предложения, а не уже работающие функции.

Официальные источники: [создание бота](https://core.telegram.org/bots/features#creating-a-new-bot),
[получение команд](https://core.telegram.org/bots/api#getupdates),
[отправка сообщений](https://core.telegram.org/bots/api#sendmessage),
[пауза при ограничении запросов](https://core.telegram.org/bots/api#responseparameters).
