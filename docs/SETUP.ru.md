# Установка из нового клона

**Русский** · [English](SETUP.md)

Команды рассчитаны на Ubuntu/WSL и выполняются в корне проекта, где `manage.py`.
Подготовленному рабочему окружению переустановка не требуется.

```bash
git clone https://github.com/Sasambatra/django-salon-booking.git
cd django-salon-booking
```

Клон содержит исходники и пример настроек, без базы, секретов и установленной `.venv`.

## 1. Требования

Проверенный стек: Python 3.14 с venv, PostgreSQL 18 с psql и работающим сервером,
Git, Bash. Для копий нужны pg_dump/pg_restore. Эти инструменты проект автоматически
не устанавливает. Сборка Node/npm не требуется.

## 2. Зависимости Python

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install --only-binary=:all: -r requirements.txt
.venv/bin/python -m pip check
```

Версии закреплены в requirements.txt; установка использует wheel, не сборку из исходников.

## 3. Приватные настройки

```bash
.venv/bin/python scripts/init_env.py
```

Команда создаёт закрытый `.env` по примеру, генерирует ключ Django, не печатает
его и не заменяет существующий файл. Откройте `.env` в редакторе и задайте
`DB_PASSWORD`. По умолчанию email сохраняется в файлы.
Формат — Bash-присваивания; пароли со специальными символами заключайте в кавычки.
Публикуется только `.env.example`, без настоящих значений.

## 4. PostgreSQL

На новом Ubuntu-сервере откройте административную консоль:

```bash
sudo -u postgres psql
```

В ней создайте отдельную роль и базу, пароль задайте интерактивно:

```sql
CREATE ROLE room_booking WITH LOGIN CREATEDB;
\password room_booking
CREATE DATABASE room_booking OWNER room_booking;
\q
```

`CREATEDB` нужен для временной тестовой базы; superuser не требуется. Укажите те
же значения в `.env`. Существующие роли/базы сохраняйте. В другой ОС выполните
эквивалентные действия в её средстве администрирования PostgreSQL.

## 5. Миграции и демо-данные

```bash
set -a
source .env
set +a
.venv/bin/python manage.py migrate
.venv/bin/python manage.py setup_demo
```

`set -a` экспортирует прочитанные настройки, `set +a` выключает автоэкспорт.
Миграции создают схему. `setup_demo` добавляет недостающую стрижку, двух мастеров
при их отсутствии и владельца, если администратора ещё нет. Существующие записи
и пароли сохраняются.

Приватно прочитайте `.local/owner-access.txt`. Пароль не печатается в журнал.
Локальный владелец использует зарезервированный адрес example.test. Первый вход
в админку требует аутентификатор и подтверждение пароля. Общего публичного пароля нет.

## 6. Проверка и запуск

```bash
bash scripts/check.sh
bash scripts/run.sh
```

Проверки используют отдельную PostgreSQL-базу и останавливаются при ошибке.
`run.sh` сам читает `.env`, использует существующую `.venv`, ничего не устанавливает.
Откройте [каталог](http://127.0.0.1:8000/services/) или
[о студии](http://127.0.0.1:8000/about/). Остановка — Ctrl+C в терминале сервера.
Другой порт: `bash scripts/run.sh 127.0.0.1:8001`.
Изменения Python обычно перезагружаются; после `.env` или переводов перезапустите сервер.

## Почта и язык

После регистрации/восстановления пароля:

```bash
.venv/bin/python manage.py show_email
```

Команда показывает последнее локальное письмо в приватном терминале. Перейдите
по ссылке в том же браузере; наружу письмо не отправлено.
Язык сайта выбирается браузером, кнопки сохраняют выбор на год; резервный язык —
русский. Время остаётся московским, суммы — в рублях. После правки PO-каталога:

```bash
.venv/bin/python scripts/compile_translations.py
```

Компиляция использует стандартную библиотеку, затем нужен перезапуск.
Снимки бронирований и собственные имена не переписываются. Новым названиям услуг
нужны явные записи представления/каталога.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Нет DJANGO_SECRET_KEY или DB-настройки | Загрузите `.env` в текущий терминал |
| Connection refused | Сервер PostgreSQL, DB_HOST и DB_PORT |
| Password authentication failed | DB_PASSWORD и пароль отдельной роли |
| Нельзя создать тестовую базу | Право CREATEDB у роли разработки/тестов |
| Нет мастеров | `setup_demo` в нужной базе |
| Неизвестен пароль владельца | Сохраните существующий доступ; setup_demo не сбрасывает администратора |
| Устарел перевод | Перекомпилируйте каталог и перезапустите сервер |
